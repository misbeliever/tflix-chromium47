# C47.5: Exit, one-time pairing and Node 4 review

## Exit

Reproduced the old behaviour: a no-op window.close() still caused exitApp() to return success. The new code detects the TizenBrew loopback module route and goes back through browser history, matching the host's own module-return behaviour. When a real Tizen application exit API is available outside that route, it is still used. Missing exit mechanisms now leave an explanatory message instead of silently pretending to quit.

Reviewed TizenBrew v2.0.5 commit d6a797b0b270d65adcbaab64c5c10e0f5fac49b5: Modules.jsx navigates with location.href; tizenbrew-ui/src/main.jsx handles module Back with history.back(). Source: https://github.com/reisxd/TizenBrew/blob/d6a797b0b270d65adcbaab64c5c10e0f5fac49b5/tizenbrew-app/TizenBrew/tizenbrew-ui/src/main.jsx . This is an app/module exit, not a TV power action. Direct module URLs without launcher history need the available platform API or the TV's Home button. Actual TV exit remains a hardware test.

## Pairing

Enter the Mac's plain address once on TV, then approve the matching code on Mac. Separate TV credentials persist on both sides; the TV automatically reconnects after reopening. The Mac keeps its stable admin credential and only the TV credential hash in a private user-owned settings file; no credentials are committed or bundled. Disconnect pauses; Forget pairing clears/revokes. Details: companion/README.md.

## Node 4 double-check

The TV serviceFile remains the self-contained ES5 hlsRelay-node4.js from C47.3. Re-ran the actual Node 4.4.3 launcher-style VM checks, including health/pairing, provider install/load/resolve/uninstall, HLS relative/init URL rewriting, ranged media and origin/LAN/path/error cases. The browser code is separately built as ES5 for Chromium 47 and all source modules are syntax-checked. Exit and companion persistence/security self-checks also pass.

Remaining limits: external provider scripts are NOT automatically transpiled, so async/newer API dependencies can still fail under Node 4. The old runtime's TLS/certificate capabilities may not work with every current upstream site; local fixtures do not validate external providers or HTTPS interoperability. Browser codecs, iframe behaviour and DRM are separate from Node compatibility. Default/GogoAnime playback, live TV exit and live remembered pairing were not verified by these local checks. No Node, root or firmware changes were made.
