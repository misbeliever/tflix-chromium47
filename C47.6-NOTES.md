# C47.6: relay VM startup and readable Mac address

## Reproduced problem and fix

TizenBrew 2.0.5 copies most host globals into its service VM. Its copied Function/Object globals led the bundled URL polyfill to install into the host realm, leaving URLSearchParams undefined in the service VM. The service then threw before opening port 47994. This was reproduced using the released C47.5 bundle under actual Node 4.4.3 and the corrected launcher-style VM test.

The builder now explicitly binds globalThis to the service VM’s top-level this before the generated bundle runs. It preserves the strict-mode directive. The earlier C47.3–C47.5 minimal test context missed the copied-globals condition; those passing checks overstated host fidelity. scripts/check-relay-node4.cjs now mirrors the copied-globals setup from TizenBrew v2.0.5 serviceLauncher rather than relying on fresh VM built-ins.

## Mac address

The input was already type=text in C47.4/C47.5. C47.6 explicitly sets foreground/background/text-fill colours and disables WebKit text masking. A separate visible Address line repeats its current value. The exact cause of the TV’s underscore appearance is not confirmed. Module name and sidebar badge show C47.6 to identify stale installations. Existing storage keys and C47.5 pairing/server protocol are unchanged.

## Checks completed

- Production build and ES5 parsing of the service and all legacy browser chunks.
- Actual Node 4.4.3 with copied host globals: health, URL/HTTP handling, pairing, fixture provider install/load/resolve/uninstall, playlist rewriting/ranged media, incompatible provider errors and Origin/LAN/path guards.
- Exit routing and companion persistence, restart, authorization, revocation and browser adapter checks.
- Desktop Chrome running the classic legacy bundle with selected modern APIs disabled: C47.6 badge, editable plain address, matching visible readout, explicit light text/dark background, no captured page errors.

These tests use local synthetic provider/media fixtures. No successful default/GogoAnime install or playback on the TV is claimed. External provider scripts are not transpiled and may require newer syntax/APIs. Node 4 TLS/certificates, provider sites, media codecs and DRM remain separate possible limits. No root, Node replacement or firmware changes were made. No actual pairing credentials or TMDB keys are included.

## Upgrade and device check

1. Update the existing misbeliever/tflix-chromium47 module to C47.6 without resetting app data. Fully exit and reopen TFlix; if the host retains the old service, restart TizenBrew (or the TV normally).
2. Confirm both the module name and sidebar badge show C47.6. If an old badge appears, the new built files have not loaded; do not reset your TMDB/history to fix a cached build.
3. In Settings, check Local relay first. Only retry a provider pack after it reports reachable. If it still fails, report the exact error and whether the C47.6 badge is visible.
4. Open Mac companion. The plain Mac address should be readable both inside the field and below it. The existing C47.5 Mac companion works; no new key or re-pair is required for an already saved connection. Otherwise use the Mac page’s plain TV address and approve the matching code once.

TizenBrew’s native removal-confirmation appearance is postponed at the user’s request. This module update cannot change that host-owned dialog.
